# إصدار نسخة البيع (مثبّت ويندوز) والتراخيص

أوركيفا بيتباع كبرنامج مثبّت على جهاز العميل (Orqiva-Setup-x.y.z.exe). العميل بيشغّله وبيفتح نافذة البرنامج، والبيانات بتتحفظ في مجلد المستخدم (`%APPDATA%\Orqiva`) فالتحديث أو إعادة التثبيت مبيمسحش حاجة. الكود بيتحزم جوه البرنامج.

## أولًا: مرة واحدة فقط، مفاتيح الترخيص بتاعتك

```
npm ci
npm run license -- keygen vendor.pem
```

- `vendor.pem` ده **المفتاح الخاص**. احتفظ بنسخة احتياطية آمنة ومتحطوش على GitHub ولا على جهاز عميل. لو ضاع مش هتقدر تطلع مفاتيح جديدة، ولو اتسرب أي حد يقدر يطلع مفاتيح.
- الأمر بيطبع سطر `ORQIVA_LICENSE_PUBLIC_KEY=...`. القيمة اللي بعد `=` هي **المفتاح العام** (مش سري).

## ثانيًا: بناء المثبّت (الطريقة الموصى بها: على GitHub)

1. في GitHub: Settings > Secrets and variables > Actions > New repository secret. الاسم `ORQIVA_LICENSE_PUBLIC_KEY` والقيمة هي المفتاح العام من الخطوة الأولى.
2. Actions > "Windows installer" > Run workflow (على main).
3. لما يخلص (حوالي 10 دقايق) نزّل الملف من Artifacts باسم `Orqiva-Setup`. الـ workflow بيجرّب المثبّت بنفسه على ويندوز (تثبيت صامت، تشغيل، فحص الصحة) قبل ما يطلّعه.

لو مفيش secret، الـ workflow بيبني نسخة **تجريبية مفتوحة** (كل الإضافات شغالة من غير ترخيص). متبيعهاش.

بديل على جهاز ويندوز عندك: حط المفتاح العام في ملف `packaging/license-public-key.txt` وشغّل `npm ci` ثم `npm run dist:win`، والمثبّت بيطلع في `release/`. (من لينكس مش بيشتغل من غير wine، فاستخدم GitHub.)

## ثالثًا: تطلع مفتاح لكل مشتري

```
npm run license -- issue vendor.pem --customer "اسم العميل" --addons crm,loyalty --expires 2027-12-31
```

- كل مفتاح بيشمل **الترخيص الأساسي** (النظام كله). `--addons` أسماء الإضافات الاختيارية (crm, loyalty, backup) أو `'*'` للكل أو سيبها فاضية للنظام الأساسي بس. `--expires` اختياري، من غيره المفتاح بلا نهاية.
- الأمر بيطبع سطر طويل. العميل بيلصقه في: الإعدادات > الترخيص.
- بدون مفتاح ساري: النظام كله مقفول وبيظهر شاشة "تفعيل النظام" (قبل تسجيل الدخول) لحد ما العميل يلصق المفتاح. بيانات العميل بتفضل على جهازه.
- المفتاح بيفتح النظام الأساسي، وكل إضافة (CRM، الولاء، النسخ الاحتياطي) لازم تكون مذكورة في المفتاح عشان تشتغل.
- لإضافة إضافة لعميل: أطلع له مفتاح جديد (بنفس الاسم والإضافات الجديدة) وهو يلصقه في الإعدادات > الترخيص.
- مفاتيح اتطلعت قبل التغيير ده من غير حقل الأساسي بتتعامل كأنها بتشمل الأساسي (محدش بيتقفل).
- النسخة المفتوحة (من غير مفتاح عام): نسخة التطوير والاختبار، كل حاجة شغالة من غير ترخيص ومتتباعش. ملف الـ workflow بيسمّي الناتج `Orqiva-OPEN-TEST-do-not-sell` عشان متتلخبطش مع `Orqiva-Setup` المرخّصة.
- للتحقق من مفتاح: `npm run license -- verify <المفتاح-العام> <المفتاح>`.

## إصدار المفاتيح من صفحة على النت (بدل الأوامر)

الصفحة `tools/license-keygen/index.html` بتطلّع مفتاح الترخيص من المتصفح من غير أوامر. بتدخل اسم العميل والإضافات وتاريخ الانتهاء (اختياري) وتلصق المفتاح الخاص، وتاخد المفتاح الناتج.

- التوقيع بيتم جوه المتصفح بس. المفتاح الخاص مبيتخزنش ومبيتبعتش، والصفحة ممنوعة من الاتصال بالإنترنت (CSP).
- المفتاح الخاص يتلصق بصيغة الـ seed (44 حرف) أو ملف PEM كامل.
- للنشر على Netlify: Add new site > Import from Git > اختار المستودع. الإعدادات بتتاخد من `netlify.toml` (من غير build command). اختار الصفحة بروابط خاصة ومتشاركهاش.
- بتحتاج متصفح حديث (Chrome 137+ أو Safari 17+ أو Firefox 129+).

## الحماية في نسخة البيع

- المفتاح العام بقى **جوه كود البرنامج** (مش ملف بيتمسح). لو حد مسح أو غيّر أي ملف أو متغير بيئة، النسخة المرخّصة بتفضل مقفولة. النسخة المفتوحة بتتبني بس بـ `--open` (التطوير والاختبار).
- كود السيرفر مضغوط ومُشفّر جزئيًا (obfuscated) وجوه ملف app.asar، وبرنامج التشغيل بيتأكد إن ملف السيرفر زي ما اتبنى وإلا بيرفض يشتغل.
- الـ DevTools والقوائم مقفولة في النسخة المرخّصة، وأعلام Electron الأمنية (fuses) مفعّلة: منع تشغيله كـ Node، ومنع تحميل كود من خارج app.asar، وفحص سلامة app.asar.
- حدود: ده بيوقف النسخ والتعديل العادي. شخص متمرّس ممكن يفك JavaScript ويعدّل، ولا توجد حماية كاملة لأي برنامج على جهاز العميل. المفتاح لسه مش مربوط بجهاز.

## أول تشغيل عند العميل

- بيتعمل حساب المدير `admin@orqiva.com` بكلمة مرور عشوائية بتظهر في رسالة وبتتحفظ في ملف `بيانات-الدخول-الأولى.txt` جوه مجلد البيانات. يغيّرها ويمسح الملف.
- لو العميل عنده أجهزة تانية على نفس الشبكة بتفتح البرنامج من المتصفح على `http://<عنوان-الجهاز>:3001` (ويندوز هيسأل عن السماح في الجدار الناري).

## حدود لازم تعرفها (نسخة 1)

- المفتاح مش مربوط ببصمة جهاز العميل: نفس المفتاح ممكن يتنسخ على جهاز تاني. الربط بالجهاز محتاج تطوير إضافي.
- التوقيع على المثبّت (Code Signing) مش متفعل، فويندوز SmartScreen هيعرض تحذير "ناشر غير معروف" للعميل. شهادة توقيع مدفوعة بتشيله.
- التحديث تلقائي مش موجود: العميل بيثبّت النسخة الجديدة فوق القديمة.
- الفاتورة الإلكترونية (ETA) لازم تفضل متقفلة (`stub`) لحد ما يتوصّل توقيع CAdES حقيقي وتتقبل فاتورة تجريبية.
